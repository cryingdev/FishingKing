# 배경음(BGM) 파이프라인 — MIDI 작곡 → FluidSynth 렌더 → OGG

- **이 문서가 다루는 것**: 배경음을 만드는 방법(작곡 스크립트, 빌드 명령, 산출물), 큐(cue) 목록과 각 큐의 작곡 지침, 게임이 큐를 쓰는 규칙
- **관련 코드**: `Tools/Music/fk_music.py`, `Tools/Music/build.py`, `Tools/Music/cues/*.py`, `Assets/Scripts/Audio/Music.cs`(런타임), `Assets/Resources/Data/music.json`
- **관련 문서**: [README](../../README.md) · [구조](../../Docs/architecture.md) · [테스트 스위치](../../Docs/testing.md) · [배경음 런타임](../../Docs/music.md)

효과음은 지금처럼 코드로 합성하고(`Assets/Scripts/Audio/Sfx.cs`), **배경음만** 이 파이프라인으로 만듭니다.
곡은 Python으로 음표를 적어 **MIDI**로 쓰고, GM 사운드폰트(FluidR3_GM, MIT 라이선스)로 **FluidSynth**가 렌더한 뒤,
루프 지점을 이어 붙이고 음량을 맞춰 **OGG**로 저장합니다. MIDI 원본(`Tools/Music/midi/<cue>.mid`)도 커밋하므로 DAW에서 열어 고칠 수 있습니다.

## 1. 준비와 빌드

```bash
# Ubuntu / Debian
sudo apt-get install fluidsynth fluid-soundfont-gm vorbis-tools
pip install mido numpy scipy
# 다른 사운드폰트를 쓰려면: export FK_SF2=/path/to/your.sf2

python Tools/Music/build.py                    # 모든 큐
python Tools/Music/build.py stage_lake title   # 큐 id 또는 cues/ 모듈 이름으로 골라서
python Tools/Music/build.py --lint             # 렌더 없이 자동 검사만
python Tools/Music/build.py --describe title   # 텍스트 피아노 롤
# 모르는 옵션은 거부하고, 모듈 하나가 실패해도 나머지 큐는 계속 만듭니다
```

산출물:

| 경로 | 내용 |
|---|---|
| `Tools/Music/midi/<cue>.mid` | 큐 전체(모든 스템, 1회 반복) MIDI. 트랙 이름 = `스템:트랙` |
| `Assets/Resources/Audio/Music/<cue>_<stem>.ogg` | 스템별 오디오 (44.1 kHz 스테레오, `oggenc -q 2`) |
| `Assets/Resources/Data/music.json` | 게임이 읽는 큐 목록 (`fk_music.register`) |
| `Tools/Music/_tmp/reports/<cue>.txt` | 피아노 롤 + 린트 + 레벨 (git에 안 올라감) |

## 2. 작곡 스크립트 규칙

- `Tools/Music/cues/<module>.py` 하나가 `songs()` 함수로 `fk_music.Song` 목록을 돌려줍니다. 큐 id = `Song.cue`.
- **스템(stem)** = 게임이 동시에 틀고 실시간으로 섞는 층. 한 큐의 스템은 같은 템포·같은 길이라서 샘플 단위로 맞물립니다.
  각 트랙은 스템 하나에 속합니다. 스템끼리는 화성이 맞아야 하고, 한 스템만 틀어도 곡으로 들려야 합니다.
- `kind="loop"`는 끊김 없이 반복됩니다. 3회 렌더해 가운데를 잘라 쓰므로 루프 끝에서 이어지는 잔향·긴 음이 처음에 자연스럽게 겹칩니다.
  **루프 끝 마디는 첫 마디로 자연스럽게 돌아가게** 쓰세요(딸림화음으로 끝내거나 첫 마디를 향하는 경과음).
  음표는 루프 길이 안에서 시작해야 합니다(끝을 넘어 울리는 것은 괜찮음).
- `kind="sting"`은 한 번만 재생되는 짧은 곡입니다(뒤쪽 무음은 잘림).
- 음량: `Song.loudness`(기준 믹스의 RMS, dBFS)에 자동으로 맞춥니다. `mixes`는 함께 틀릴 수 있는 스템 조합(피크 검사), `ref`는 음량 기준 조합입니다.
  스템 사이의 상대 음량은 트랙 `vol`과 벨로시티로 정합니다.
- 결정적이어야 합니다: 무작위는 `song.rng`(큐 id로 시드)만 쓰고, `random` 모듈을 직접 쓰지 마세요.
  `humanize()`는 모든 트랙이 난수 하나를 나눠 쓰므로, 음표를 하나 더하거나 빼면 그 뒤 트랙들의 흔들림이 모두 바뀝니다(피크·음량이 0.5 dB쯤 달라질 수 있음).
- 렌더 처리: 모든 렌더에 12 Hz 하이패스를 겁니다(`fk_music.DC_CUT`). FluidR3의 일부 패드(warm_pad, sweep_pad, soundtrack 등)에는 큰 직류 성분이 있어 음량·피크 계산을 부풀리기 때문입니다.
  sting은 피크보다 60 dB 낮아지는 지점에서 자릅니다(`fk_music.STING_FLOOR`). FluidSynth의 파일 렌더는 모든 음이 사라질 때까지 이어지므로 `Song.tail`은 사실상 영향이 없습니다.
- 표현(CC11)의 `swell()`은 루프를 넘어 이어집니다. 루프는 3회 렌더의 가운데를 쓰므로, 마지막 마디에서 끝난 표현 값이 첫 마디로 그대로 넘어갑니다(게임의 반복과 같음).
  MIDI 파일(`midi/<cue>.mid`)은 처음에 CC11 = 127로 시작하므로 DAW에서 첫 회만 다르게 들릴 수 있습니다.
- 드럼 트랙(`DRUMS`)은 모두 MIDI 10번 채널이라 한 스템에 둘 이상 두면 볼륨·팬·리버브 설정이 서로 덮어씁니다. 한 스템의 타악기는 트랙 하나에 모으세요(린트가 WARN).
- 린트(`--lint`)가 보는 것: 조성 밖 음(INFO), 음역(WARN), 함께 울릴 수 있는 스템(`mixes`) 사이 박 위의 단2도·장7도 충돌(WARN), 드럼 트랙 채널 공유(WARN),
  같은 채널·같은 음·같은 틱의 겹친 타격(INFO), 빈 마디, 반복도(16분 격자 기준), 루프 지점의 큰 도약(INFO).
  박 사이(엇박)의 충돌과 3온음은 보지 않으므로, 필요하면 직접 확인하세요. 타이코·멜로딕 톰·효과음 계열(GM 113, 115–127)은 음높이 검사에서 뺍니다
  (FluidR3에서 타이코와 멜로딕 톰은 건반 하나에 약 50센트만 움직입니다).
- 게임 대표 모티프 `fk_music.MOTIF`(장조 음계 도수, 4마디: 솔 도 레 미— 레 도 | 라 솔 미 솔 레— | 솔 도 레 미 솔 미 | 레 미 레 도—)를
  타이틀·지도·팡파르에서 인용해 곡들이 한 게임으로 묶이게 합니다. `Track.motif()`로 쓸 수 있습니다.
- 듣지 않고 쓰는 곡이므로 `--describe` 피아노 롤과 `--lint`(조성 밖 음, 음역, 박 위의 단2도 충돌, 빈 마디, 반복도, 루프 지점 도약)를 반드시 확인하세요.

## 3. 큐 목록 (작곡 지침)

공통: 기다리는 시간이 긴 게임이라 **귀를 피곤하게 하지 않는 것**이 가장 중요합니다. 낚시 바탕곡은 멜로디가 쉬는 마디를 충분히 두고(전체의 25% 이상),
환경음(물·바람·동굴, `Sfx.Ambience`)이 들릴 여백을 남깁니다. 음색은 16비트 게임 느낌에 부드러운 실제 악기 느낌을 섞습니다(GM 음색).
날카로운 사각파 리드는 피합니다.

### 3.2 스테이지 바탕곡 (7곡 × 스템 3개)

큐 `stage_<id>`, 모듈 `stage_<id>.py`, loop, 스템 `day` · `night` · `fight`, `mixes=[["day","fight"],["night","fight"]]`, `ref=["day"]`, 음량 −21.

- `day`(새벽·낮)와 `night`(저녁·밤)는 **같은 화성 진행·같은 형식**이고 편성과 밀도만 다릅니다(시간대가 바뀌면 게임이 8초에 걸쳐 크로스페이드).
  `night`는 더 성기고 어둡고 부드럽게.
- `fight`는 파이트 중에 바탕 위에 **더해지는 층**입니다: 드럼·추진력 있는 베이스·오스티나토(필요하면 현 스타카토). `day`·`night` 어느 쪽과도 화성이 맞아야 하고,
  바탕의 멜로디를 겹쳐 연주하지 않습니다. 게임이 장력에 따라 이 층의 음량을 0.55–1.0으로 움직입니다.
- 길이 60–90초. 형식은 A–B 정도로, 8마디마다 변화를 줍니다.

| `sting_escape` | ~2초 (렌더 2.9초) | 물고기를 놓치거나 줄이 끊겼을 때 | 하행하는 단조·반음계, 피치카토 + 뮤트 트럼펫, 가볍게 아쉬운 느낌 |
| `sting_omen` | ~4초 (렌더 5.0초) | 전설어 전조가 시작될 때 | 낮은 스웰: 리버스 심벌 + 낮은 합창/콘트라베이스 상승, 불협 |
| `sting_hook` | ~2.5초 (렌더 3.0초) | 조우에서 전설어를 걸었을 때 (파이트 곡 직전) | 충격: 오케스트라 히트 + 팀파니 + 크래시 + 금관 스탭 |
| `sting_fail` | ~3초 (렌더 3.4초) | 조우 실패(돌아섬) | 불협 저음 현이 떨어지며 사라짐 |

## 4. 게임이 큐를 쓰는 규칙 (런타임 계약, `Assets/Scripts/Audio/Music.cs`)

| 상황 | 큐 / 스템 |
|---|---|
| 타이틀 · 지도 · 수족관 | `title` · `map` · `aquarium` (씬 전환 시 1.5초 크로스페이드) |
| 낚시 (대기·준비·회수 등) | `stage_<id>`: 새벽·낮 = `day`, 저녁·밤 = `night` 스템 (시간대 전환 시 8초 크로스페이드) |
| 입질 | 바탕을 잠깐 낮춤(덕킹) |
| 파이트 | `fight` 스템을 올림 (장력에 따라 0.55–1.0), 파이트가 끝나면 3초에 걸쳐 내림 |
| 잡음 | 희귀도에 따라 `sting_catch` / `sting_rare` / `sting_legend` (재생 중 바탕은 낮춤) |
| 놓침 · 줄 끊김 | `sting_escape` |
| 전설어 전조 | 바탕이 사라지고 `sting_omen` |
| 조우 | `encounter`: 열림·눈빛 = `lurk`, 접근 = `+approach`, 유인·코 들이밀기 = `+tease`, 덮침·챔질 창 = 모두 잠깐 무음 (`encounter`가 없으면 창 내내 무음) |
| 조우에서 걸림 | `sting_hook` 후 `legend_<id>` (`legend_<id>`가 없으면 스테이지 곡 + `fight` 1.0) |
| 조우 실패 | `sting_fail` 후 스테이지 곡으로 복귀 |
| 전설어 파이트 끝 | 잡으면 `sting_legend`, 놓치면 `sting_escape`, 그 뒤 스테이지 곡으로 복귀 |

`music.json`이 없거나 메뉴·스테이지 loop 큐가 거기 없으면, 또는 적힌 loop 큐의 클립을 하나도 못 읽으면 예전의 합성 칩튠(`Sfx.Music`)이 대신합니다. 매니페스트에 `encounter`가 없으면 조우 창은 칩튠 없이 무음(창의 드론·심장 박동 효과음만; `music.json`이 없을 때도 같음), `legend_<id>`가 없으면 스테이지 곡 + `fight` 1.0(스테이지 곡도 없으면 칩튠), 없는 sting은 울리지 않습니다(`[MUSIC] missing …` 한 줄). 자세한 것은 [배경음 런타임](../../Docs/music.md) 3절.
